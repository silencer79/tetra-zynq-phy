# IST 02 — AD9361 Adapter und RX/TX-Anbindung

Quelle: `rtl/tetra_ad9361_axis_adapter.v` (191 Zeilen) und die zugehörigen
Top-Level-Stellen in `rtl/tetra_zynq_top.v`.

> **⟳ Review-Delta 2026-06-20:** AD9361-Adapter + Loopback-Mux **unverändert**. Einzige RX-Pfad-Ergänzung: `tetra_rx_iq_capture.v` (Debug, siehe ist/03).

## Modul tetra_ad9361_axis_adapter.v (191 Zeilen)

**Parameter:** `IQ_WIDTH = 16` (Default 16).

**Ports:**
- IN `l_clk` (1) — DATA_CLK vom `axi_ad9361` IP (selbe Quelle für ADC+DAC).
- IN `adc_valid_i0` (1), `adc_data_i0` (16), `adc_enable_i0` (1)
- IN `adc_valid_q0` (1), `adc_data_q0` (16), `adc_enable_q0` (1)
- IN `dac_valid_i0` (1), `dac_enable_i0` (1), `dac_valid_q0` (1), `dac_enable_q0` (1)
- OUT `dac_data_i0` (16, reg), `dac_data_q0` (16, reg)
- IN `rst_n_lvds` (1)
- OUT `clk_lvds` (1) — Wire-Passthrough von `l_clk`.
- OUT `rx_i_lvds` (signed 16), `rx_q_lvds` (signed 16), `rx_valid_lvds` (1)
- IN `tx_i_lvds` (signed 16), `tx_q_lvds` (signed 16), `tx_valid_lvds` (1)

**Funktion:**
- RX-Pfad: rein kombinatorischer Passthrough. `adc_data_i0/q0 → rx_i/q_lvds`,
 `adc_valid_i0 → rx_valid_lvds`. Sign-Extension macht das ADI IP intern (12→16 bit).
- TX-Pfad: Sample-and-Hold-Register, 16-bit pro Kanal. Bei `tx_valid_lvds = 1`
 wird `tx_i/q_lvds` in `dac_data_i0/q0` übernommen, sonst Wert gehalten.

**State:** keine FSM. Zwei einzelne Register (`dac_data_i0`, `dac_data_q0`).

**Pipeline-Latenz:**
- RX: 0 Zyklen.
- TX: 1 `l_clk` Cycle vom `tx_valid_lvds` Pulse bis DAC-Output stabil.

**Nachbarn:**
- ↑ Instanziiert in `tetra_zynq_top.v:298` (`u_ad9361_adapter`).
- ↓ keine Submodule.

**Auffälligkeiten:**
- `adc_valid_q0`, `adc_enable_q0`, `dac_valid_*`, `dac_enable_*` sind als Ports
 vorhanden, aber funktional ungenutzt — in `synthesis translate_off`-Blöcken
 per `_unused_adc/_unused_dac` markiert (Z. 148, 187).
- Q0-Valid wird laut Kommentar parallel zu I0 vom IP gefahren und ignoriert.
- Headerkommentar verweist auf openwifi `libresdr/system_top.v` und ADI HDL.

## Top-Level-Verdrahtung in tetra_zynq_top.v

### Ports von tetra_zynq_top zum BD `axi_ad9361` IP

(Direkt aus `rtl/tetra_zynq_top.v:91–113` und Header):

- `input wire l_clk` — DATA_CLK vom IP.
- `input wire adc_valid_i0, adc_valid_q0`, `[15:0] adc_data_i0, adc_data_q0`,
 `adc_enable_i0, adc_enable_q0`, `adc_r1_mode`.
- `output wire adc_dovf` — fest auf 0 verdrahtet (Z. 342).
- `input wire dac_valid_i0, dac_valid_q0, dac_enable_i0, dac_enable_q0, dac_r1_mode`.
- `output wire [15:0] dac_data_i0, dac_data_q0`.
- `output wire dac_dunf` — fest auf 0 (Z. 343).

`adc_r1_mode | dac_r1_mode` wird im sim-only-Block als `_unused_r1` markiert (Z. 348).

### Adapter-Instanz (`u_ad9361_adapter`)

Z. 298–328 — Verbindet die rohen IP-Ports auf die tetra-Konvention:
`clk_lvds` (Top-Wire) ← Adapter-Output ← `l_clk`. RX-Wires `rx_i/q_adc_lvds`,
`rx_valid_adc_lvds` werden direkt an den Loopback-Mux (siehe unten) geführt.
TX-Wires `tx_i/q_lvds`, `tx_valid_lvds` kommen von `tetra_tx_chain`.

### Loopback-Mux (CTRL[2])

`rtl/tetra_zynq_top.v:336–338`:

```
rx_i_lvds = ctrl_loopback_en_lvds ? tx_i_lvds: rx_i_adc_lvds;
rx_q_lvds = ctrl_loopback_en_lvds ? tx_q_lvds: rx_q_adc_lvds;
rx_valid_lvds = ctrl_loopback_en_lvds ? tx_valid_lvds: rx_valid_adc_lvds;
```

`ctrl_loopback_en_lvds` ist die 2-FF-Resync (Z. 267/268, 1763–1771) von
`ctrl_loopback_en_axi` (CTRL[2] @ 0x00). Bei `=1` wird der digitale TX direkt
in den RX-Frontend gespeist (kein RF nötig).

### RX-Chain Eingangsverdrahtung

`tetra_rx_chain` (`rtl/rx/tetra_rx_chain.v`) bekommt:
- `clk_lvds`, `rst_n_lvds` (für Frontend/Demod)
- `rx_i_lvds`, `rx_q_lvds`, `rx_valid_lvds` (nach Loopback-Mux)
- `clk_sys`, `rst_n_sys` (LMAC-seitig)

Output `block1_out_sys/block2_out_sys/bb_out_sys/slot_valid_sys` etc. läuft in
`tetra_lmac` und die UL-Pipeline.

### TX-Chain Ausgangsverdrahtung

`tetra_tx_chain` (`rtl/tx/tetra_tx_chain.v`) liefert
`tx_i_lvds/tx_q_lvds/tx_valid_lvds` an `tetra_ad9361_axis_adapter`, der diese
auf `dac_data_i0/q0` in `l_clk`-Domain registriert.

### Adapter zu IP — Block Design

`rtl/tetra_system_top.v` enthält die board-level IOBUFs und instanziiert
`tetra_system_wrapper` (auto-generierter BD-Wrapper). Die LVDS-Pins
(`rx_clk_in_p/n`, `rx_frame_in_p/n`, `rx_data_in_p/n[5:0]`, sym. TX) gehen direkt
in das `axi_ad9361` IP im Block Design — dort wird LVDS DDR I/O, DDR-Kalibrierung
und AD9361-SPI gemacht. `tetra_zynq_top` sieht nur das Fabric-Interface
(`adc_*`/`dac_*` + `l_clk`).

### Status-Auffälligkeit `adc_enable_i0`

`adc_enable_i0` wird als IP-Output empfangen, im Adapter ungenutzt — das `_unused_adc`-XOR
nutzt es nur als Lint-Sink (`rtl/tetra_ad9361_axis_adapter.v:148`).
